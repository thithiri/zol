# Spike 0.4: dummy-spend zero-value check

**Result: PASS.** A signer can confirm that a dummy spend is worth zero using only fields the PCZT carries after IoFinalizer. It can also verify the dummy's attached signature. This holds for both the Orchard (NU6.2) and Ironwood (NU6.3) pools.

## Rule the gateway should implement

The fields used are all present in the coordinator's proposal after IoFinalizer. For each action the signer did **not** classify as a real vault spend (real means `rk == ak_app + [alpha]G` and the nullifier is one of the app's own notes):

1. **The paired output is pinned:**
   - recompute `cmx' = Extract(NoteCommit(recipient, value_out, rho = spend.nullifier, rseed_out, note_version))`;
   - require `cmx' == output.cmx`.
2. **Zero spend value:**
   - recompute `cv' = ValueCommit(0 − value_out, rcv)`, using the constant 0 and *not* the PCZT's `spend.value` field;
   - require `cv' == cv_net`.
3. **The dummy signature verifies:** `RedPallas.Verify(rk, sighash, spend_auth_sig)`, where `sighash` is the signer's own ZIP 244 recompute.
4. **No dummy key remains:** `spend.dummy_sk` must be absent.

**Why this is sound.** The Action circuit enforces `cv_net = [v_old − v_new]V + [rcv*]R` with `v_new` bound to `cmx`. Step 1 fixes `v_new = value_out`. Step 2 shows `cv_net = [0 − value_out]V + [rcv]R`. The binding property of the Pedersen commitment then forces `v_old = 0`.

A zero-valued dummy cannot reveal a vault note's nullifier. The nullifier depends on the note commitment, which includes the value, and the vault's notes are non-zero. Spending a vault note needs a signature under `ak_vault + [alpha]G`, which signers never give to an action they classified as "other". The proof itself is checked separately: consensus rejects an invalid proof, and ZOL signers re-verify it.

## What was tested

`spikes/zcash/tests/spike_0_4_dummy_spend.rs`, no proving needed:

1. Build the 0.3 payout PCZT and run IoFinalizer.
2. Serialize and parse again, which is what a signer receives.
3. Classify each action with `is_vault_spend` (the `rk` test against the vault FVK and the supplied alpha). This step does not trust `spend.value`.
4. **Real action:**
   - `check_real_spend`: the `rk` test, plus the nullifier must equal the signer's own `head.nullifier(fvk)`;
   - `check_cv_net(head value)`;
   - the dummy rule applied to the real action returns `Err(cv_net mismatch)`, so the rule discriminates.
5. **Dummy action:**
   - `check_dummy_zero_value` (steps 1 and 2 above): OK;
   - `check_dummy_sig` against the recomputed sighash: OK;
   - orchard's own `verify_nullifier(None)`, `verify_rk(None)` and `verify_cv_net()`, which use the dummy's own FVK carried in the PCZT: OK.
6. **Redaction probes** (the pczt `Redactor`):
   - with `rcv` cleared, the dummy check fails with "rcv missing";
   - with `output.rseed` cleared, it fails with "output.rseed missing";
   - the signature check still works in both cases.

Output of one run:

```
action 0: dummy spend; cv_net == ValueCommit(0 - 390000, rcv) OK; spend_auth_sig verifies under rk OK
action 1: real vault spend; dummy rule on it -> Err(cv_net mismatch)
rcv redacted -> dummy check: Err(rcv missing)
output.rseed redacted -> dummy check: Err(output.rseed missing)
```

## Fields present for a dummy action

| Field | After Creator | After IoFinalizer (what signers get) | Needed by the dummy rule |
|---|---|---|---|
| `spend.nullifier`, `spend.rk` | yes | yes | rho for cmx; rk for the signature |
| `spend.value` (= 0) | yes | yes | **not used** (0 is a constant) |
| `spend.recipient`, `rho`, `rseed`, `fvk`, `witness` | yes (the dummy's own random key and path) | yes | no (optional: orchard `verify_nullifier`/`verify_rk`) |
| `spend.alpha` | yes | yes | no (for a dummy) |
| `spend.dummy_sk` | **yes** | **removed** by IoFinalizer | must be absent |
| `spend.spend_auth_sig` | no | **yes** (made by IoFinalizer) | yes |
| `output.recipient`, `output.value`, `output.rseed` | yes | yes | yes (cmx) |
| `output.cmx`, `epk`, `enc_ciphertext`, `out_ciphertext` | yes | yes | cmx |
| `output.ock` | **no** (the builder leaves it `None`; see 0.5) | no | no |
| `rcv` | yes | yes (IoFinalizer reads it to make `bsk` but does not clear it) | **yes** |
| `cv_net` | yes | yes | yes |

Nothing needed is redacted by the standard roles. The pczt docs allow a Redactor to drop `rcv` and the value fields "for Signers who don't need this information". ZOL signers need them, so redacting them must be grounds to reject.

## Implications for design v0.3

- The dummy rule ("recomputing the action's value commitment from the paired output's value and the supplied randomness with a spend value of zero") works as written. Make two dependencies explicit:
  - it is sound only together with the cmx recompute on the same action;
  - the proposal must carry `rcv` and the output plaintext (recipient, value, rseed) for every action. A proposal with any of these redacted is rejected.
- Use the constant 0, not the PCZT's `spend.value` field.
- "Reject any proposal that still carries a dummy spending key" must be the gateway's own check. The pczt `Signer` does not enforce it (spike 0.6).
