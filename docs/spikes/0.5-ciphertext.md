# Spike 0.5: ciphertext reproducibility

**Result: PASS, with one condition.** `epk` and `enc_ciphertext` are byte-for-byte reproducible from the output plaintext. That plaintext is the recipient, value, `rseed`, `rho` (the action's spend nullifier) and the memo, and the PCZT carries everything except the memo. `out_ciphertext` is reproducible only when the output was built with an OVK (`ovk = Some`) and the signer knows which OVK was used. The PCZT does **not** carry the OVK, and `ock` is always `None` from the builder.

## Recommendations

1. **enc_ciphertext:** the signer computes the expected memo itself (the head memo from the chain state, the payout memo from a fixed format). It then re-encrypts and byte-compares. For a memo it cannot predict, such as a padding output's, use the decryption route instead:
   - decrypt with `pk_d` from the recipient and `esk = ToScalar(PRF^expand(rseed, [4] || rho))`, using `try_output_recovery_with_pkd_esk`;
   - this succeeds only if the ciphertext decrypts to exactly the committed note (it checks the AEAD tag, then `esk` against `rseed`, `epk = [esk]g_d` and `cmx`);
   - by Diffie-Hellman, `esk·pk_d = ivk·epk`, so the recipient's IVK decrypts it too.
2. **out_ciphertext:** fix the OVK policy so signers can recompute it:
   - payouts use the vault's external OVK;
   - the new head uses the vault's internal OVK;
   - padding outputs are added explicitly by the coordinator as zero-valued outputs to throwaway addresses, with a vault-derived OVK.

   Do not let the builder pad outputs implicitly. `OutputInfo::dummy` uses `ovk = None`, which makes `out_ciphertext` 80 random bytes that nobody can check, a free covert channel.
3. **Alternative for enc_ciphertext:** require the PCZT in pczt's compact form, where `enc_ciphertext` is `EncCiphertext::MemoPlaintext`. pczt then re-encrypts on parse and checks `epk`, so the ciphertext is correct by construction. This does not cover `out_ciphertext`.

## What was tested

`spikes/zcash/tests/spike_0_5_ciphertext.rs`, for both pools, no proving.

**Setup.** One spend and four outputs, which gives 4 actions with 3 dummy spends:

- payout, OVK = vault external;
- head, OVK = vault internal;
- zero-value padding to a throwaway address with `ovk = None`;
- zero-value padding to a throwaway address with `ovk = Some(throwaway OVK)`.

**Checks.** After IoFinalizer and a serialize/parse round trip, for each output:

- `checks::recompute_enc`: rebuild `Note::from_parts(recipient, value, Rho(nf), rseed, note_version)` and run `OrchardNoteEncryption::new(None, note, memo)`. The resulting `epk` and 580-byte `enc_ciphertext` match the PCZT byte for byte. Running it twice gives the same bytes. Flipping one memo bit changes the result.
- `checks::recover_with_esk`: recovers the memo from the PCZT ciphertext using only public PCZT data.
- `checks::recompute_out`:
  - OVK `Some(k)`: `ock = PRF^ock(k, cv_net, cmx, epk)`, then ChaCha20-Poly1305 with nonce 0 over `pk_d || esk`;
  - it matches for exactly the OVK used, and for no other;
  - for `ovk = None` it matches nothing.
  - The function is called with an RNG that panics if touched, which proves the recompute is deterministic.
- `output.ock` is `None` for every output.
- **pczt's own reliance on this:**
  - `Redactor::compact_resolvable_fields` replaced all 4 ciphertexts with memo plaintexts (6.7 kB);
  - parsing and `resolve_fields` re-encrypted them byte-identically.

Output of one run:

```
payout                 epk OK, enc_ciphertext(580B) OK, memo-by-esk OK; out_ciphertext reproduced by ["ovk_ext"]
head                   epk OK, enc_ciphertext(580B) OK, memo-by-esk OK; out_ciphertext reproduced by ["ovk_int"]
padding/ovk=None       epk OK, enc_ciphertext(580B) OK, memo-by-esk OK; out_ciphertext reproduced by []
padding/ovk=throwaway  epk OK, enc_ciphertext(580B) OK, memo-by-esk OK; out_ciphertext reproduced by ["ovk_throwaway"]
pczt compact encoding: 4 of 4 outputs carried as memo plaintext, re-encrypted on parse byte-identically
```

## Which randomness and which OVK make it deterministic

| Component | Derived from | In PCZT? |
|---|---|---|
| `esk` | `ToScalar(PRF^expand_rseed([4] ‖ rho))` (ZIP 212) | `rseed` yes, `rho = spend.nullifier` yes |
| `epk` | `[esk] g_d` | yes (and recomputable) |
| `enc_ciphertext` key | `KDF(esk·pk_d, epk)` | yes (all inputs) |
| note plaintext | lead byte (0x02 Orchard / 0x03 Ironwood), d, value, rseed, memo | all but the memo; the memo comes from the expected format or from esk-decryption |
| `ock` | `PRF^ock(ovk, cv_net, cmx, epk)` | `ovk` **no**; `ock` field **always None** (orchard `builder.rs`: "TODO: Extract ock from the encryptor and save it") |
| `out_ciphertext` if `ovk = None` | random `ock` and random plaintext from the builder RNG | not reproducible |
| AEAD nonce | constant zero | n/a |

Can a third party reproduce it?

- **enc_ciphertext: yes.** Anyone holding the PCZT can, with no keys, because the memo is recoverable through `esk`.
- **out_ciphertext:** only someone who knows the OVK used, so the vault's signers can for vault-OVK outputs. A pure third party cannot.

## Implications for design v0.3

- The Ciphertexts bullet holds: "each output's ciphertext is the encryption of that plaintext to that recipient, recomputed and compared". Add the following to the design:
  - **OVK policy:** payout uses the external OVK, the head the internal OVK, padding a vault-derived padding OVK, and `ovk = None` is never used. Signers recompute `out_ciphertext` too.
  - **Padding:** the coordinator adds padding outputs explicitly so the builder never pads with `ovk = None`. Dummy *spends* have no ciphertext of their own, so they are unaffected.
  - **Payout memo:** fix its format so that signers can predict it. Otherwise use the esk-decryption check.
- Close the open decision "Whether an Orchard output ciphertext is byte-for-byte reproducible": yes, for both Orchard V2 and Ironwood V3 notes.
