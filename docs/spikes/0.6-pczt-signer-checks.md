# Spike 0.6: what the `pczt` Signer checks, and what the ZOL gateway must add

**Result: DONE.** The inventory comes from reading pczt 0.9.3 and orchard 0.15.5, and four executable probes back it. The headline: the pczt Signer checks almost nothing about what the transaction *does*. It computes the sighash itself, which is the one valuable property, and checks that the key matches `rk`. Everything in the design's recompute checklist is the gateway's job.

## What the pczt Signer does by itself

Source: `pczt/src/roles/signer/mod.rs`, `orchard/src/pczt/{signer,verify,parse}.rs`.

| Check | Done by the Signer? | Where |
|---|---|---|
| Structural parse of every field: point, scalar and FVK encodings, `Rho`, `RandomSeed`, ciphertext lengths, flags under the bundle version, note version | yes | `Signer::new`, then `extract_tx_data`, then `into_parsed_with_version` (orchard `parse.rs`). The FVK goes through `FullViewingKey::from_bytes`, which enforces ỹ(ak) = 0 and ivk ≠ 0. |
| Redacted `cv_net`, `cmx` and memo-form `enc_ciphertext` are recomputed (`resolve_fields`) | yes, but only when they are absent. If present they are **not** checked. | `pczt/src/orchard.rs` `resolve_fields` |
| **Shielded sighash computed from the parsed effects** (ZIP 244, v5 or v6) | **yes** | `Signer::new`, then `sighash(&tx_data, Shielded, &txid_parts)` |
| tx version and version group are consistent with the branch; an Ironwood bundle only in v6 | yes | `extract_tx_data` |
| Nullifier of the spend being signed is consistent with its note fields | **only if** `recipient`, `value`, `rho` and `rseed` are all present. Otherwise silently skipped. It uses the PCZT's own `spend.fvk` (`verify_nullifier(None)`), so it checks internal consistency and **not** that the note belongs to the signer's vault. | `generate_or_apply_orchard_signature` |
| The signing key matches the spend: `ask.randomize(alpha)` → `rk` must equal `spend.rk` | yes (`sign_orchard`/`sign_ironwood`) | orchard `pczt/signer.rs` `Action::sign` |
| An external signature verifies under `rk` before it is stored | yes (`apply_orchard_signature`) | orchard `Action::apply_signature` |
| Updates `tx_modifiable` flags | yes | |
| Rejects a PCZT that still carries `dummy_sk` ("Signers MUST reject" in the field docs) | **no** (probe 1) | |
| `cv_net` vs values and `rcv` | **no** (probe 3: signs with every `rcv` redacted) | `Action::verify_cv_net` exists but is not called |
| `cmx` vs output plaintext | **no** | `Output::verify_note_commitment` exists but is not called |
| `rk` vs the vault key | **no** (only the signing key vs `rk`) | `Spend::verify_rk` exists but is not called |
| `enc_ciphertext` / `out_ciphertext` | **no** (probe 4) | nothing in pczt or orchard checks `out_ciphertext` |
| `user_address` contains `recipient` (field docs: "Signers must parse this address") | **no** | |
| Cross-address restriction (docs: caller "should call `verify_cross_address_restriction`") | **no** in the Signer. IoFinalizer and Prover enforce it. | |
| Proof | **no** (the Signer may run before the Prover) | |
| Value balance, fee, expiry, anchor freshness, which notes are spent, which addresses are paid | **no** ("It is the caller's responsibility to perform any semantic validity checks") | |
| Dummy-spend signatures | **no** | |

**Other roles, for completeness:**

- **IoFinalizer:**
  - checks the cross-address restriction;
  - checks that `rcv` is present on every action;
  - sets `bsk` and checks `[bsk]R == Σcv_net − ValueCommit(value_sum, 0)`, so `value_sum` is consistent with `cv_net`;
  - signs the dummies and clears `dummy_sk`.
- **Prover:**
  - requires the FVK and all note fields;
  - `SpendInfo::new` must accept the FVK and note;
  - each non-zero spend's witness must root to the anchor (`verify_witnesses_root_to_anchor`);
  - checks the cross-address restriction and the rho chain;
  - rejects an identity `rk`.
- **TxExtractor:**
  - requires every `spend_auth_sig`, the proof and `bsk`;
  - requires a canonical proof size, a non-identity `rk` and a valid `epk`;
  - requires every `spend_auth_sig` to verify under the sighash it recomputes (`apply_binding_signature`);
  - signs `bindingSig`;
  - batch-verifies proof and signatures (`BatchValidator`).
- **SpendFinalizer:** transparent only, so it is a no-op here.

## Probes

`spikes/zcash/tests/spike_0_6_signer_checks.rs`:

```
1  Signer::new + sign with dummy_sk present: Ok; dummy_sk still present after signing: true
2  sign with wrong ask:                Err(OrchardSign(WrongSpendAuthorizingKey))
   sign dummy action with vault ask:   Err(OrchardSign(WrongSpendAuthorizingKey))
   apply garbage external signature:   Err(OrchardSign(InvalidExternalSignature))
3  sign with every rcv redacted:       Ok(())
   sign with spend.value + spend.rseed redacted (nullifier unverifiable): Ok(())
4  (both pools)
   tamper after IoFinalizer -> TxExtractor: Err("SighashMismatch")
   gateway: recomputed enc_ciphertext != proposal; esk-decryption fails -> REJECT
   pczt Signer signed it; TxExtractor + independent verify OK
   recipient trial-decryption of the mined payout: none -> 600000 zat burned
```

Probe 4 is the attack the design anticipates:

1. A malicious coordinator flips one byte of the payout's `enc_ciphertext` *before* it runs IoFinalizer.
2. Proof, dummy signatures, FROST or single-key signature, binding signature and `BatchValidator` all pass. The proof does not cover ciphertexts, and the signature covers whatever ciphertext it was given.
3. The independent raw-transaction verification passes, so the transaction is consensus-valid.
4. The recipient's trial decryption fails, so the payout is burned. Only the gateway's recompute rejects it.

A byte flipped *after* IoFinalizer is caught by pczt itself: the dummy signatures commit to the original effects, so TxExtractor fails with `SighashMismatch`. That only protects against third parties, not against the coordinator.

## Checks the ZOL gateway must add

Each signer applies these to its own parse of the PCZT bytes, never trusting a derived value.

1. **Shape:**
   - the consensus branch for the current height; tx version 5 or 6; pool;
   - Ironwood after NU6.3 (see 0.3);
   - no transparent or Sapling parts;
   - flags are as expected;
   - the action count equals the batch's fixed padded count.
2. **No `dummy_sk`** in any action (0.4).
3. **Field completeness:** `rcv` and the output `recipient`, `value` and `rseed` on every action; `alpha` on every real spend. Reject if any is redacted.
4. **Classify spends:**
   - **real** iff `rk == ak_app + [alpha]G` for *this* app's key;
   - for a real spend, the nullifier must equal `note.nullifier(fvk_app)` for a note in the signer's own scan: the current head, a credited deposit note or a full-depth top-up, unspent;
   - exactly one real spend is the head.

   The nullifier check is what isolates apps from each other (see 0.8: the `alpha` relabelling).
5. **Real spends:** `cv_net == ValueCommit(v_note − value_out, rcv)`, with `v_note` from the signer's own scan.
6. **Dummy spends:** cmx recompute, then `cv_net == ValueCommit(0 − value_out, rcv)`, then `spend_auth_sig` verifies under `rk` with the signer's sighash (0.4).
7. **Outputs:**
   - recompute every `cmx` from the plaintext;
   - exactly the settlement's payouts (address from rule 5, amount);
   - exactly one output addressed to the vault, tested with the vault IVKs in both scopes over all diversifiers (`scope_for_address`); this is the new head, with the expected memo and value;
   - every other output is zero-valued and not vault-addressed;
   - if `user_address` is present, it must contain `recipient`.
8. **Ciphertexts (0.5):** `epk` and `enc_ciphertext` re-encrypted from the expected memo and byte-compared, or esk-decryption for padding. `out_ciphertext` recomputed with the OVK the policy prescribes.
9. **Value balance and fee:**
   - `value_sum == fee`, checked through `bsk`/`bvk` or by summing values;
   - fee = ZIP 317 for the action count, and no more than the fee pool;
   - expiry height within a bound of the current height.
10. **Anchor:** a tree root the signer's own node has seen (the Prover checks the witnesses). In v6 the anchor is not covered by the sighash.
11. **Proof:** run `Bundle::verify_proof` with the pinned verifying key for the circuit version, or verify after the signatures are collected. In both cases, never broadcast without verifying.
12. **Sighash:** take it from `Signer::new(...).shielded_sighash()` or from an independent ZIP 244 recompute (`spikes/zcash/src/verify.rs`), and sign exactly that value. The spike checks that the two agree.
13. **Randomizer:** `alpha` must be present, non-zero and canonical, must satisfy `rk = ak_app + [alpha]G`, and must reach the signer over a confidential channel (ZIP 312).

## Exact versions

pczt 0.9.3, orchard 0.15.5, zcash_primitives 0.30.1, zcash_protocol 0.10.6.

## Implications for design v0.3

- Close the open decision "Which checks the `pczt` signer role already performs": only the sighash, the key-to-`rk` match, signature validity and structural parsing.
- Every item in "Building and checking the payout" is a gateway check. Add the explicit items from the list above that the design does not yet state:
  - rejecting redacted fields;
  - the OVK policy and `out_ciphertext` recompute;
  - the `user_address` check;
  - the per-app nullifier binding;
  - the note that the v6 sighash does not cover the anchor.
- Probe 4 is a ready-made adversarial test for plan 4.11 ("a wrong ciphertext").
